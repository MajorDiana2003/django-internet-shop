
# Интернет-магазин на Django: База данных, модели и фикстуры

Проект представляет собой вторую часть разработки интернет-магазина на веб-фреймворке **Django 5**. В рамках этой работы проект переведён на профессиональную СУБД **PostgreSQL**, реализована связанная структура моделей данных, настроена продвинутая панель администратора, сформированы фикстуры данных, отработаны навыки ORM-запросов в Django Shell и создана кастомная консольная команда для управления базой [jork58, o2AYzq].

## 🎯 Архитектура и ключевые модули проекта

### 1. База данных, модели и фикстуры
* **СУБД PostgreSQL/SQLite:** Настроено гибкое переключение конфигураций баз данных. Вся конфиденциальная информация вынесена в изолированные переменные окружения (`.env`).
* **Архитектура данных:** Реализована связанная структура моделей `Product`, `Category` и `Blog` с использованием связей `ForeignKey`.
* **Автоматизация данных:** Написана кастомная консольная команда `python manage.py fill_db`, которая автоматически очищает базу данных от старых записей и корректно загружает новые тестовые данные из JSON-фикстур, выстраивая связи между объектами.

### 2. Приложение catalog (Магазин)
* **Перевод на CBV:** Все ключевые контроллеры (главная страница, контакты, добавление, детальный просмотр, редактирование и удаление товаров) переписаны с функций на классы-ориентиры (`ListView`, `DetailView`, `CreateView`, `UpdateView`, `DeleteView`).
* **Безопасность форм:** Все POST-запросы и формы защищены обязательным токеном `{% csrf_token %}`.
* **Строгая типизация:** Весь код приложения полностью аннотирован типами для успешного прохождения статических проверок утилитой `mypy`.

### 3. Приложение blog (Блог проекта)
* **Полный CRUD:** Реализован сквозной цикл управления блоговыми записями (вывод списка, просмотр, создание, редактирование и удаление).
* **Автогенерация URL:** Ссылки на статьи формируются динамически с использованием человекочитаемых слагов (`slug`), автоматически генерируемых на латинице с помощью библиотеки `pytils`.
* **Автоматический счетчик:** Реализован инкремент количества просмотров при каждом посещении детальной страницы публикации.
* **Фильтрация:** На главную страницу блога выводятся исключительно статьи с активным флагом `is_published=True`.

### 4. Приложение users (Кастомная авторизация)
* **Авторизация по Email:** Стандартная модель пользователя Django расширена через наследование от `AbstractUser`. Поле `username` полностью отключено, а уникальным идентификатором для входа в систему сделан `email`.
* **Кастомный профиль:** К модели пользователя добавлены три дополнительных поля: аватар (`avatar`), номер телефона (`phone`) и страна проживания (`country`).
* **Продвинутая регистрация:** Реализована форма регистрации с кастомной валидацией, включающей обязательное поле подтверждения пароля. При успешном создании аккаунта пользователю отправляется автоматическое приветственное email-уведомление.

### 5. Права доступа и модерация контента
* **Контроль владельцев:** К модели продуктов добавлено поле `owner`. При создании любого товара его создатель автоматически закрепляется в базе данных. Изменять или удалять товар разрешено строго его владельцу.
* **Группа «Модератор продуктов»:** Создана кастомная консольная команда `python manage.py create_moderator`, разворачивающая в базе данных специальную роль модератора.
* **Разграничение прав доступа:** Модераторы наделены системным правом удаления любого товара, а также кастомным разрешением `can_unpublish_product` для принудительной отмены публикации неподходящих продуктов.
* **Динамический UI:** Кнопки редактирования и удаления товаров автоматически скрываются в HTML-шаблонах с помощью проверок условий `{% if %}`, если текущий пользователь не имеет на это прав.

### 6. Оптимизация и кеширование (Redis)
* **Кеширование страниц:** Контроллер детального просмотра информации о продукте (`ProductDetailView`) обернут в декоратор `cache_page` для снижения нагрузки на сервер при частых запросах к популярным товарам.
* **Низкоуровневый сервис:** В модуле `catalog/services.py` разработан изолированный сервисный слой для работы с категориями.
* **Сервисное кеширование:** Функция `get_products_by_category` принимает ID категории, проверяет оперативную память кеша по ключу `category_{id}`, считывает данные напрямую из базы только при их отсутствии и сохраняет список с заданным TTL.

## Стандарты кодирования и проверка стиля

В проекте строго соблюдаются стандарты оформления кода PEP 8 (с ограничением длины строки в 119 символов). Перед коммитами выполняется автоматическая проверка кода утилитами:

1. **Сортировка импортов:** `isort blog catalog --line-length 119`
2. **Форматирование кода:** `black blog catalog --line-length 119`
3. **Статический линтинг:** `flake8 blog catalog`
4. **Проверка статической типизации:** `mypy catalog`

## 🚀 Инструкция по запуску
1. Сделайте копию файла `.env.sample`, назовите её `.env` и укажите ваши параметры подключения к базе данных и настройки кеширования.
2. Установите необходимые пакеты и зависимости проекта:
   ```bash
   pip install -r requirements.txt
   ```
3. Выполните миграции для автоматического построения структуры таблиц:
   ```bash
   python manage.py migrate
   ```
4. Наполните базу данных исходными тестовыми категориями и товарами из фикстур:
   ```bash
   python manage.py fill_db
   ```
5. Разверните в базе данных группу модераторов с настроенными правами доступа:
   ```bash
   python manage.py create_moderator
   ```
6. Запустите локальный сервер разработки Django:
   ```bash
   python manage.py runserver
   ```
7. Откройте сайт в браузере: http://127.0.0.1:8000
