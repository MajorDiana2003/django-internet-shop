
# Интернет-магазин на Django: База данных, модели и фикстуры

Проект представляет собой вторую часть разработки интернет-магазина на веб-фреймворке **Django 5**. В рамках этой работы проект переведён на профессиональную СУБД **PostgreSQL**, реализована связанная структура моделей данных, настроена продвинутая панель администратора, сформированы фикстуры данных, отработаны навыки ORM-запросов в Django Shell и создана кастомная консольная команда для управления базой [jork58, o2AYzq].

## 🎯 Цели и задачи проекта
* Интегрировать СУБД **PostgreSQL** вместо стандартного решения SQLite [jork58].
* Вынести секретные ключи, пароли и настройки подключения базы в изолированные переменные окружения (`.env`) [jork58].
* Разработать связанные модели данных **Продуктов** и **Категорий** с использованием связи `ForeignKey` [jork58].
* Сформировать фикстуры данных формата JSON для категорий и продуктов [Bcxymb].
* Написать кастомную управляющую команду (`management command`), использующую системную утилиту `loaddata` для фикстур [jork58, Bcxymb].
* Отработать базовые CRUD-операции с базой данных через интерактивную консоль **Django Shell** [o2AYzq].

## 🛠️ Выполненные требования и критерии оценки
1. **Переход на PostgreSQL**: Настроено подключение к базе данных. Все зависимости зафиксированы в файле `requirements.txt` [jork58].
2. **Сокрытие данных (.env)**: Секретные настройки вынесены в файл `.env`. В корне репозитория подготовлен демонстрационный файл `.env.sample`. Файл секретов добавлен в `.gitignore` [jork58].
3. **Архитектура моделей**: Созданы две связанные модели — `Category` и `Product`. Организована связь «Один ко многим» через `ForeignKey`. Реализованы методы `__str__` и классы `Meta` с параметрами `verbose_name` и `verbose_name_plural` [jork58].
4. **Фикстуры и кастомная команда**: Сформированы фикстуры в файле `catalog/fixtures/catalog_data.json` [Bcxymb]. Написана кастомная команда `python manage.py fill_db`, которая перед наполнением очищает базу данных от старых категорий и продуктов, а затем корректно загружает фикстуры в БД через встроенную команду `loaddata`, выстраивая связи между объектами [jork58, Bcxymb].
5. **Кастомизация админки**: Для продуктов настроен вывод ID, наименования, цены и категории. Добавлена фильтрация по категориям и поиск по названию/описанию. Для категорий настроен вывод ID и названия [jork58].
6. **Интерактивный Shell**: В консоли Django отработаны операции создания объектов категорий и продуктов, выборки всех записей, фильтрации по внешнему ключу, обновления полей и удаления записей. Скриншоты терминала приложены к отчету [o2AYzq].
7. **Дополнительные задания**: Реализована модель `ContactInfo` для хранения контактов в базе данных. В контроллере главной страницы настроен вывод последних 5 продуктов в консоль при каждом обращении [jork58].

### Приложение `catalog` (Магазин)
- **Перевод на CBV:** Контроллеры главной страницы, контактов, добавления и детального просмотра товаров полностью переписаны с функций на классы (`ListView`, `DetailView`, `CreateView`, `View`).
- **Строгая типизация:** Весь код приложения полностью аннотирован типами для успешного прохождения проверок статического анализатора `mypy`.

### Приложение `blog` (Блог)
- **Полный CRUD:** Реализован сквозной цикл управления блоговыми записями (вывод списка, просмотр, создание, редактирование и удаление) на базе Generic Views.
- **Автогенерация URL:** Ссылки на статьи формируются динамически с использованием человекочитаемых слагов (`slug`), автоматически генерируемых на латинице с помощью библиотеки `pytils`.
- **Автоматический счетчик:** Реализован инкремент количества просмотров при каждом посещении детальной страницы публикации.
- **Фильтрация:** На главную страницу блога выводятся исключительно публикации с флагом `is_published=True`.
- **Почтовые уведомления:** Интегрирована логика отправки email-поздравления автору при достижении публикации знаковой отметки в 100 просмотров. Для тестирования используется консольный backend.

## Стандарты кодирования и проверка стиля

В проекте строго соблюдаются стандарты оформления кода PEP 8 (с ограничением длины строки в 119 символов). Перед коммитами выполняется автоматическая проверка кода утилитами:

1. **Сортировка импортов:** `isort blog catalog --line-length 119`
2. **Форматирование кода:** `black blog catalog --line-length 119`
3. **Статический линтинг:** `flake8 blog catalog`
4. **Проверка статической типизации:** `mypy catalog`

## 🚀 Инструкция по запуску
1. Сделайте копию файла `.env.sample`, назовите её `.env` и укажите ваши параметры подключения к PostgreSQL [jork58].
2. Установите необходимые пакеты:
   ```bash
   pip install -r requirements.txt
   ```
3. Выполните миграции для создания таблиц:
   ```bash
   python manage.py migrate
   ```
4. Наполните базу тестовыми данными из фикстур с помощью нашей кастомной команды [jork58, Bcxymb]:
   ```bash
   python manage.py fill_db
   ```
5. Запустите сервер разработки Django:
   ```bash
   python manage.py runserver
   ```
## Проверка типов (mypy)

Для проверки статической типизации проекта используются инструменты статического анализа. Запуск проверки:
```bash
mypy catalog
```

# Интернет-магазин на Django (Часть 1)

Проект представляет собой стартовую версию интернет-магазина, разработанного на веб-фреймворке **Django 5**. В рамках этой работы заложена базовая архитектура приложения, настроена маршрутизация страниц и внедрён движок шаблонов.

## 🎯 Цели и задачи проекта
* Изучить структуру и принципы работы фреймворка Django.
* Настроить изолированное виртуальное окружение и зафиксировать зависимости.
* Реализовать архитектуру разделения логики (Проект `config` + Приложение `catalog`).
* Внедрить шаблонный движок Django для рендеринга адаптивных HTML-страниц [jork58].
* Настроить обработку статических файлов (CSS-стилей Bootstrap) [jork58].

## 🛠️ Выполненные требования
1. **Django-архитектура**: Создан проект `config` и изолированное приложение `catalog`. Приложение успешно зарегистрировано в `INSTALLED_APPS`.
2. **Маршрутизация**: В файле `urls.py` прописаны пути для Главной страницы (`/`) и страницы Контактов (`/contacts/`).
3. **Шаблонизатор (Views & Templates)**: Реализован рендеринг HTML-файлов с помощью встроенной функции `render()` [jork58]. Файлы организованы в корневой папке `templates/`.
4. **Работа со статикой**: Настроена раздача статических файлов. Стили Bootstrap подключены локально через тег `{% static 'css/bootstrap.min.css' %}` [jork58].
5. **Безопасность и POST-запросы**: Форма контактов защищена обязательным токеном `{% csrf_token %}`. На бэкенде реализован перехват данных (Имя, Телефон, Сообщение) и их вывод в терминал PyCharm.
6. **GitFlow**: Настроена структура веток `main`, `develop` и рабочая ветка для решения текущей задачи [YWBDL8].

## 🚀 Инструкция по запуску
1. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```
2. Запустите сервер разработки Django:
   ```bash
   python manage.py runserver
   ```
3. Откройте сайт в браузере: http://127.0.0.1:8000

   - Главная страница магазина: http://127.0.0
   - Блог проекта доступен по адресу: http://127.0.0blogs/
